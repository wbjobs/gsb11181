# 跨标签页共享计数器

一个无后端、无第三方依赖的浏览器计数器。多个同源标签页共享同一个 IndexedDB，BroadcastChannel 只负责实时通知。

## 功能

- 加一、减一、重置为 0
- 设置任意安全整数目标值
- 标签页刷新、关闭后重新打开不丢计数
- 离线或实时消息中断期间可继续操作，恢复后重新读取并合并
- 消息重复、乱序或内容无效不会产生重复更新

## 一致性设计

每个操作先在当前标签页串行入队，再在 IndexedDB `readwrite` 事务中完成“读取全部操作 → 生成下一条操作 → 写入”的原子步骤。

操作字段包含：

- `id`：`source:seq`，用于幂等去重
- `source`：每个标签页的唯一 ID
- `seq`：同一标签页内递增序号
- `clock`：Lamport 逻辑时钟

所有标签页按 `(clock, source, seq)` 对操作日志排序，再纯函数归约出当前值：

- `increment`：当前值加一
- `decrement`：当前值减一
- `reset`：当前值置零
- `set-target`：当前值设置为目标值

BroadcastChannel 消息不作为状态本身，只触发接收方重新读取 IndexedDB。因此消息乱序、重复或临时收不到都不会修改或丢弃操作日志。标签页启动、重新可见、浏览器恢复在线、消息恢复和定时恢复都会重新拉取日志。

## 本地运行

```bash
npm start
```

然后打开：

- 计数器：http://localhost:8000/index.html
- 自动验收：http://localhost:8000/stress.html

## 自动验收

打开 `stress.html` 后点击“运行验收”。页面会打开 4 个独立窗口并检查：

1. 4 个窗口各加 100 次后全部为 400
2. 4 个窗口同时重置后全部为 0
3. 一个窗口关闭后已提交计数仍存在
4. 实时消息中断期间的本地操作恢复后合并正确
5. 重复、乱序、无效消息不丢更新
6. 刷新任意窗口后计数一致
7. 设置目标值和减一归约正确

纯算法测试运行：

```bash
npm test
```

## 边界说明

这是单机浏览器方案，IndexedDB 是同一浏览器用户配置下的同源共享存储，不包含服务端同步、历史页面、用户系统或权限控制。当前实现为保持简单不做日志压缩；验收规模很小。Web Worker 在此方案中是可选项，当前 UI 和 IndexedDB 工作已经足够轻量，因此没有引入额外线程。
